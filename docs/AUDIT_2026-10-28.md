# 2026-10-28 代码与官方文档核对

## 核对依据（微软原始文档）

- MediaCapture.InitializeAsync：首次调用应从应用主 UI/STA 线程发起；不能把初始化简单丢到 Task.Run，更不能在 UI 上同步 Wait。
  https://learn.microsoft.com/en-us/uwp/api/windows.media.capture.mediacapture.initializeasync
- Process media frames with MediaFrameReader：共享只读模式不允许修改源格式；帧资源需要明确释放；向 XAML 显示前规范为 BGRA8/Premultiplied；串行投递并丢弃过期预览。
  https://learn.microsoft.com/en-us/windows/apps/develop/camera/process-media-frames-with-mediaframereader
- Create, edit, and save bitmap images：XAML Image 格式限制、SoftwareBitmap.CopyToBuffer / CopyFromBuffer、BitmapEncoder 保存流程。
  https://learn.microsoft.com/en-us/windows/apps/develop/media-authoring-processing/imaging
- Collecting User-Mode Dumps：WER LocalDumps 要管理员配置 HKLM，支持按应用指定 DumpFolder、DumpType、DumpCount；路径必须有写权限；自动调试器等因素会影响转储。
  https://learn.microsoft.com/en-us/windows/win32/wer/collecting-user-mode-dumps
- WiX PermissionEx：MSI 5.0 的 CreateFolder 可用 SDDL 设置数据目录权限。
  https://docs.firegiant.com/wix/schema/wxs/permissionex/

## 已发现并修改的问题

1. 活跃采集路径中的 UI 同步等待：删除 RunSync、Task.Wait、Result、GetResult。设备枚举、初始化、格式选择、启动、停止沿调用链异步执行；快速切换取消旧请求并串行管理设备生命周期。超时是异步等待上限，不等于取消了底层驱动。
2. 原来的 _previous 从未被赋值；每次换入新帧后丢掉 old 引用，造成 unmanaged bitmap 泄漏。延迟一帧释放也不保证读者完成。改用锁保护的一份最新帧，拍照/显示各取得自己的副本并在使用完成后释放。
3. 原来每帧派发到 Dispatcher，再由主窗口二次派发，且没有限定第一层队列。改成无位图参数的 FrameAvailable 信号，主窗口最多一个队列项/异步提交在途。
4. 原格式探测只测试创建读取器，不验证启动状态或实际帧。现在检查 StartAsync 返回枚举，等待第一帧规范化成功；每阶段及失败 HRESULT 写入日志。
5. SharedReadOnly 下仍 SetFormatAsync：独占模式才设置格式，共享模式记录实际输入而不改变源；读取器输出尺寸受限，显示始终规范为 BGRA8/Premultiplied。
6. 原“显示 FPS”数的是事件投递，不是显示完成。现在计数 SetBitmapAsync 成功完成，界面明确标为“提交”；不是显示器刷新率、远程客户端 FPS 或编码帧率。
7. 多处 Debug.WriteLine 在 Release 被编译移除；旧日志超过 1MB 删除全部历史。改用统一 AppLog，不按文件大小抹掉当天日志。
8. WinUI 全局异常一律 Handled=true 掩盖未知严重故障。现在记录完整 Exception.ToString、HRESULT、会话、进程/线程并同步刷盘，不一律吞掉致命异常。AppDomain 未处理异常和未观察任务异常另设记录。
9. 配置保存先删旧文件再重命名、无写入锁且退出不刷盘。改为唯一临时文件、刷盘后替换、串行写入、退出最后一次保存。
10. JPEG ImageQuality 原来 double 配 Single，改为显式 float。
11. 命令栏冒泡指针事件可能误触发窗口拖动；限制为空白区域左键按下。
12. 扫描算法占 UI：移到后台执行并禁止重复提交。现有扫描器仅计算轴对齐四边，不具备真正单应性透视校正；已改正界面宣传，未把它当成完成的透视矫正。

## 用户数据布局

所有本应用新写入的配置、日志、媒体、缓存和临时文件位于：

```text
<应用目录>/Users/
├── <Windows 用户 SID>/
│   ├── Config/settings.json
│   ├── Logs/YYYY-MM-DD.log
│   │   └── Archives/YYYY-MM.tar.gz
│   ├── Crashes/                   # 托管异常详情、异常退出会话标记
│   ├── Media/Photos/
│   ├── Media/Scans/
│   ├── Media/Recordings/
│   ├── Cache/
│   ├── Temp/                      # 包括会话运行标记
│   └── Migration/                 # 旧版日志/设置迁移记录
└── Shared/CrashDumps/             # WER，主程序和启动器 mini dump
```

- 数据跟随安装盘：装 D 盘，Users 就在 D；仍装 C 盘则仍占 C 盘。
- 只修改 Users 数据树 ACL，不允许普通用户修改安装目录里的 EXE/DLL。
- 按 SID 分类是逻辑分类；安装器授予本机 Users 对数据树的修改权限，并非隔离不同用户的安全沙箱。
- 不可写时明确报错，不偷偷回退到 AppData。便携版放 Program Files 不会自动获得权限。
- 配置与旧 vdc.log 首次复制迁移，原件不删除。旧图片/录像不自动大批搬移、不删除；新文件使用新路径。
- 更新/卸载不删除 Users。安装器排除 Users 打包，Git 也忽略 Users，避免上传用户资料。
- 修改进程级 TEMP/TMP/TMPDIR；不能承诺 Windows、驱动、安装器或运行时自身绝不写系统盘。

## 日志与归档约定

- 使用本机日期命名（YYYY-MM-DD.log），每条含毫秒时间、时区、级别、分类、PID、TID、会话 ID。
- 记录启动环境、设备 ID、输入/输出格式、阶段开始/结束、第一帧、首次 SetBitmapAsync 成功、五秒性能汇总、保存路径、完整异常及退出。
- 完整上月及更早月份在启动和每小时维护时归档。十月运行会归档九月；十月日志不会提前压缩。
- 用户所写 .tag.gz 按标准 tar+gzip 的 .tar.gz 实现，例 2026-09.tar.gz。
- 流式打包，不把整月读入内存。临时包逐条 SHA-256/长度校验后替换正式包；只删除与已验证条目相同的原件；冲突/失败保留原件。
- 崩溃文本同步刷盘。异常退出标记只证明没有正常关闭，不能凭它猜崩溃原因。
- UI 后台心跳检测记录疑似卡死，不伪造阻塞线程调用栈。

## 崩溃记录边界

EXE/MSI 安装器为 VideoPresenter.exe 和 VideoPresenter.Launcher.exe 配置应用级 WER mini dump，各保留最多五份。便携版没有安装器执行这一项。管理员策略、自动调试器、系统状态可能使 WER 不生成 dump。强制断电、taskkill /F、栈溢出等不能保证由托管事件完整记录。没有全量内存转储默认上传；dump 可能含用户数据，分享前应审查。

保留 portable PDB 便于故障栈定位到源码行。版本号未改。
